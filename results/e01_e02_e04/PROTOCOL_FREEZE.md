## 6. E4: null controls (receiver-only action, content-free input changes)

**Runner per population**

- Receiver only; no helper or fuser is loaded.
- Small and large OBQA and ARC: P2_10 `runtime` + `arc_runtime_adapter`. The receiver is loaded exactly as `runtime.Runner.__init__` does.
- Medium: execution_retry1 `native_runtime`. The receiver is loaded as `Runtime.__init__` does.
- MMLU-Pro: MMLU stage 1 `native_runtime`, which patches the prompt to `format_mmlu`. The receiver is loaded as `Runtime.__init__` does.
- Requests go through the same `Runner.request(q, 'receiver_only')` and `T2TReceiverBundle.consume` methods.

**Variants**

- **V1 "perm":** the option list is rotated by one position, so original option i sits at position (i+1) mod K, and labels are re-assigned by position (A, B, …).
  - Request: `Runner.request(v1_query, 'receiver_only')`.
  - The parsed displayed label at position p maps back to the original label at index (p−1) mod K. INVALID stays INVALID.
- **V2 "irrelevant message":** the paper's Text-reference receiver prompt for question i, with only the assistant (helper) turn replaced by the saved `helper_message` of position (i + floor(N/2)) mod N, from the same pair and population.
  - Messages: user = BACKGROUND_PROMPT(helper_body(question i)); assistant = foreign message; user = receiver prompt(question i).
  - Request: `T2TReceiverBundle.consume(q_i, format_openbook(q_i, use_template=False), message_j)`.
  - A login-node check substituted each population's own message and reproduced the paper's saved Text receiver input exactly (same token count; identical token IDs where they were saved).
- **V0 (supplementary, not requested):** an unchanged receiver-only replay in this job, run only after V1 and V2 on the same GPU. It measures run-to-run and hardware drift relative to the saved R. It is not used in the requested E4 metrics.

**Metrics per population**

- Correct counts for R (saved), V1 and V2.
- Oracle over {R, V1, V2}, and its gain over the best of the three in percentage points: 100·(oracle − max)/N.
- Answer-change rates R vs V1 and R vs V2 (answer symbols, INVALID treated as a symbol).
- The paper's oracle over {R, Text, C2C}, recomputed from saved outputs and checked against `P2_FOCUSED_REVISION_ROUND1_CPU_EVIDENCE_AUDIT_20260918T065337Z/outputs/T1_complementarity.csv`.

- The feature computation is unchanged:
  - receiver backbone prefill of the rendered `receiver_prompt` (`src/receiver_prompt.py`, byte-identical copy, SHA-256 868a4760…), with `enable_thinking=False`;
  - capture at the last valid token of `model.layers[k]` output[0] and `model.norm` output;
  - each vector L2-normalised in FP32, concatenated, divided by √2.
  - The dev extraction in `P2_RISK_CALIBRATION_BINARY…/src/extract_dev.py` is the same computation, with k=25 for large.
- **Layer indices** (the extractor hard-codes a per-model `ac_block_index`): small k=19 of 28, large k=25 of 36 (verbatim from the E1 frozen config). Medium (Qwen3-1.7B, 28 layers, hidden 2048) uses the same relative depth. The rule is the formula P2-10 used for small→large: j = floor((k_small+1)·L/L_small + 0.5), k = j−1. For medium this gives k=19.
- **Dimensions:** small 2048, medium 4096, large 8192.
- **Settings:**
  - small: OBQA dev 742, ARC dev 299;
  - large: ARC dev 299, MMLU-Pro fit 3000, cal 6000, dev 2641 (representatives);
  - medium: OBQA fit 2100, cal 1366, dev 742; ARC fit 671, cal 448, dev 299.
- **Output:** `results/e2b/<pair>/features/<setting>/<row:05d>.npz` (`z`, `meta`).

## 2. Arms

Four arms per deployed policy, on the same frozen 128-question panel, in **one** allocation, rotated
by question ordinal so that each arm occupies each of the four positions equally often (32 questions
per (arm, position) cell). The rotation is `arms[k:] + arms[:k]` with `k = ordinal mod 4`, the same
rule as E3.

1. **FIXED** — the fixed reference (Text or C2C), exactly as in E3. Behaviour byte-identical to the
   frozen driver.
2. **ORIGINAL** — the deployed policy as in E3: the full ProbeMax probe (`use_cache=False`, no reuse
   of anything), then a **fresh, complete** request — receiver-only `R` if the probe omits, otherwise
   the reference. Behaviour byte-identical to the frozen driver.
3. **REUSE** — the probe's prefill KV cache is kept. On **omitted** questions the receiver-only answer
   is generated by continuing from that cache, cropped to the longest common token prefix with the
   native `R` prompt; any remaining native `R` prompt tokens are prefilled. On **kept** questions the
   reference runs exactly as in arm (2). The probe itself is timed **in full**, including allocating,
   keeping and cropping the cache.
4. **ARGMAX** — on **omitted** questions the answer is the probe's argmax label, with **no** `R`
   request at all; on kept questions the reference runs exactly as in arm (2). The omission decision
   uses `q_A` from the CPU re-certification of 2026-09-19 (`e7/E7_ARGMAX_RECERT.json`), not the
   deployed `q`. Settings with `q_A = 0` have **no** ARGMAX arm. The probe is timed in full.

### 2.1 Measured prefix relation (fixed before the freeze)

Verified on the login node 2026-09-19 (`e7/E7_PREFIX_CHECK.json`), with the frozen tokenisation, for
both receivers and all five panels (128 questions each, 640 in total): the native `R` prompt is an
**exact token prefix** of the ProbeMax probe input in **640/640** cases. The probe input is the `R`
prompt followed by exactly the 4 tokens `[785, 4396, 4226, 374]` ("The correct answer is").

Consequence for arm (3): the longest common prefix is the whole `R` prompt. Because the frozen probe
projects only its **last** position through `lm_head`, no logits exist for the last `R` prompt
position, so the cache is cropped to `len(R) - 1` and the final `R` prompt token is re-prefilled. This
is the "remaining prompt tokens, if any, are prefilled" case of the rule above, with exactly one
remaining token. It is stated here, before any output, and is not a later deviation.

### 2.2 What arm (3) may change and what it may not

The probe of arm (3) runs with `use_cache=True` instead of `use_cache=False` so that the cache
survives; the returned ProbeMax score, label distribution, argmax and `probe_ids_sha256` must be
**identical** to the frozen probe. The extra cost of keeping and cropping the cache is inside the
timed probe region. Arms (1) and (2) keep `use_cache=False` and are unchanged.

## 3. Timing, statistics and reporting

- **No warm-up.** No synthetic forward passes. One model residency per node.
- **Cold requests are kept** in the records and in analysis version (a).
- One outer synchronised wall timer per request, exactly as in E3: input preparation, probe, selector,
  complete native action including decode and parser V2, and cleanup. I/O, diagnostics and any gold
  read are outside the timer.
- Batch size 1, greedy decoding, bf16, SDPA, TF32 off, zero retries.
- Analysis versions: **(a)** all requests and **(b)** cold questions excluded — the same two versions
  as E3.
- **2000 paired bootstrap resamples, seed 0**, resampling panel questions, as in E3.
- **Single run.** No repeats, no second submission.
- Numbers are **not** compared with the original hardware. Savings are classified, not equated across
  machines.

Reported per policy and per arm:

- mean saving against the fixed-reference arm, with its interval, and the class
  **above zero / crosses zero / below zero**;
- the paired median saving;
- the Text/C2C saving ratio per benchmark.

On the panels, **every** REUSE output that differs from the native `R` output of the same question is
reported individually (id, panel, both raw strings, both parsed labels).

## 4. Validation before the replay

Per receiver (Qwen3-8B and Qwen3-1.7B), on 16 fit questions, **no gold read**:

- the REUSE path's **raw output string** must equal the saved `R` output for the same question.
  If more than **1 of 16** differ for a receiver, **STOP** and report; the replay is not submitted.
- the ARGMAX label must equal the saved probe argmax label on those same 16 questions (exact match
  required on all 16).

## 5. Job layout

One 2-node ClusterA `debug` job, `-l fsreq=<fs>`, walltime `00:50:00`:

- **node A** — large/OBQA (Text, C2C) and large/ARC (Text, C2C) panels;
- **node B** — MMLU-Pro (Text, C2C), medium/OBQA (C2C) and medium/ARC (C2C) panels.

Budget from the E3 ClusterA logs (job 7635399, repeats 2 and 3, which had normal per-request overhead
of 0.01–0.02 s; repeat 1 hit node-local contention of 1.8 s/request and is treated as the pessimistic
case): node A ≈ 13 min, node B ≈ 16 min of replay time, plus model load. Both fit the 50-minute cap
with margin; under repeat-1-style contention node B would still complete inside the walltime.

## 6. Prohibited

No retuning of any threshold, no new calibration, no new fit, no gold read during validation or the
replay, no resubmission after a completed or failed formal replay, no warm-up, and no editing of
arms (1) and (2).
